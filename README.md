# VELOOP Rewards · Data Analyst Internship · Task 01

**Product Analytics, Data Readiness & Data Management Blueprint**

> **Integrity notice.** All data in this repository is **simulated**. It was either supplied by VELOOP for this task (`VELoop_Rewards_Data_01.xlsx`) or generated by the analyst and labelled `SIMULATED DATA — CREATED FOR ANALYTICAL TESTING`. No number here is an actual VELOOP user, earning, withdrawal, revenue, retention, conversion or performance figure. Every event, field, table and KPI is a **proposal** that engineering has not yet verified.

## Key findings

1. The supplied workbook contains **only Users data**. The other seven datasets the brief describes were generated under section 28, labelled as simulated, and documented in [`data/simulated/GENERATION_METHODOLOGY.md`](data/simulated/GENERATION_METHODOLOGY.md).
2. The supplied structure is a **snapshot**: of 14 KPIs tested, 9 cannot be computed from it and 4 only partially.
3. The supplied "clean" sheet has logical defects: sessions without active days, logins without sessions, marketing opt-in without consent, and activity flags built on an undocumented reference date.
4. Rule-based quality checks found every planted defect: 12/12 cells and 8/8 duplicates in the supplied messy sheet, and 90/90 defects in the generated Messy_Data, with 0 false positives.
5. Public sources conflict (homepage user/payout figures and crypto payouts vs the brief and the help center). They were recorded as unverified and not used.

## Repository structure

```
deliverables/          21 deliverables (.md + .xlsx), PDFs, diagrams/, wireframes/
data/simulated/        analyst-generated simulated datasets + methodology + injection log
data/raw/              supplied workbook (git-ignored; fetch with scripts/fetch_data.py)
scripts/specs/         single source of truth: dictionary, events, KPIs, model, registers, operations
scripts/               generate -> profile -> audit -> build -> diagrams -> site -> validate
site/                  static site deployed to Vercel/Netlify
```

## How it stays consistent

Every spreadsheet and document is **generated** from `scripts/specs/` and the computed statistics. No count is typed by hand. `scripts/validate.py` runs cross-consistency checks and fails the build if anything disagrees. It checks that:

* every event property, KPI field and ER field exists in the data dictionary;
* event names follow `object_action`, and every brief-minimum event exists;
* every KPI, assumption, source, gap, rule and backlog ID referenced anywhere exists;
* simulated data uses only allowed values and every row carries the simulated label;
* data-quality detection matches the injection log exactly;
* no KPI contains a target, and no document has leftover placeholders.

## Reproduce

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/fetch_data.py
cd scripts && ../.venv/bin/python run_all.py
```

The ER diagram and PDFs need Node (for `npx @mermaid-js/mermaid-cli`) and Google Chrome. Without them the committed copies are kept.

## Deploy

The site is static. Vercel (`vercel.json`) and Netlify (`netlify.toml`) both publish the `site/` folder, with no build command.

## Tech

Python (pandas, openpyxl, numpy), Mermaid for the ER diagram, hand-built SVG for the pipeline and wireframes, and static HTML for the site.
